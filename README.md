# Repair Scores

The `gh-pages` branch serves the public device explorer. Python collection code,
source checks and the daily publication workflow live on `master`.

The interface includes device/model-number search, manufacturer and score filters,
selectable page sizes, CSV export, device comparisons, versioned iFixit rubrics,
French criteria and source evidence, and a zoomable image viewer. English is the
interface language. French and iFixit values remain separate; ambiguous variants
and conflicting sources do not acquire an invented aggregate score. Where
source configurations are explicit and internally consistent, their reported
range is labelled "By configuration"; the scalar score remains null.

## Build and browser checks

Use Node.js 24:

```sh
npm ci
npm run build
```

Edit `css/site.css`; `styles.css` is generated by the build. Lucide and JetBrains
Mono are pinned in `package-lock.json` and copied into `assets/` with their
licences. The page loads no external scripts, stylesheets or fonts. Thumbnails
are cached locally from public iFixit API image URLs. The image viewer can load
a larger source rendition, with the correct local device image as a fallback.

See [tests/README.md](tests/README.md) for Playwright checks. Run
`npm run check:assets` after committing source/build changes to verify that the
committed generated files exactly match the pinned sources.

## Automatically updated data

The daily workflow on `master` refreshes and validates:

- `devices_with_scores.json`: device scores, model identities, source evidence
  and image metadata;
- `france_devices_with_scores.json`: the French source catalogue;
- `rubric.json`: published iFixit rubric versions and revision notes;
- `french-method.json`: criteria and coefficients parsed from the published
  smartphone calculation workbook, its declared edition and observed revisions;
- `images.json` and new `assets/devices/` files: current iFixit photos.

No manual rebuild of the interface is needed when the existing data formats gain
new devices or criteria. The French workbook edition is not inferred for an
individual device, and observation dates are not treated as legal effective dates.
The old French score and the newer EU repairability class remain distinct.
Unknown workbook structures and rejected data-quality checks stop publication;
the last validated public data stays available. Previously reviewed calculation
sheets are rechecked against their source attachment and content hash before a
correction is reused.

The configured GitHub Pages branch build publishes `gh-pages` commits. The daily
import explicitly requests that build after validated generated-data changes. No Sites hosting configuration or user/API credentials belong in this branch.

## Links, freshness and dependency updates

Filters, sorting, page size, page, selections, scoring-system tabs and rubric
versions are encoded in the URL. Device links use the stable iFixit wiki title,
so source ordering changes do not redirect an old link to another device.
Back/forward restores the view; closing a device opened from the explorer returns
to its filtered list. Device names are real links and support opening a new tab.

`data-status.json` records the last published dataset change in UTC. The
methodology snapshot has its own date. Daily check results are available in the
[GitHub Actions run history](https://github.com/NoJokeFNA/ifixit-repair-score-site/actions/workflows/sync-json-to-pages.yml).

Dependabot checks the locked npm packages weekly on `gh-pages`. PR browser checks
build and test the proposed package versions. After merge, `assets.yml` rebuilds
and commits the local fonts, icons, CSS and licences, then explicitly requests a
Pages branch build. No manual generated-file commit is needed for package bumps.
